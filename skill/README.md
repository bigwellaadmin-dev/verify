# Using this skill without violating VERIFY

Read this before deploying the skill in a classroom or feedback workflow.

## The recursive problem

VERIFY teaches students not to offload their thinking to AI. This skill makes it possible for you to offload your VERIFY thinking to Claude. The framework's own diagnostic, applied to its own delivery mechanism, surfaces the same failure mode it was built to address.

This is not a flaw in the skill. It is the framework folding back on itself. The fact that the irony is visible is what makes it useful.

## What using this skill well looks like

The skill is a tool that extends your VERIFY practice. It is not a substitute for the practice itself.

- **You read what Claude generates.** If you do not read it carefully, you do not know what was said to your student.
- **You adapt feedback before sending it.** Claude does not know your student. You do. The feedback that arrives in their hands should reflect that.
- **You have the verbal-defence conversation.** Mode 3 produces the written feedback. Y still requires you to ask the student to defend their reasoning in person. The skill does not do Y for you.
- **You notice when Claude is wrong.** Claude will sometimes generate confident, well-structured, fluent feedback that is wrong about your student. Fluency is not accuracy. The check question applies here too.
- **You treat Claude's diagnostic as a hypothesis, not a verdict.** When Mode 2 says "the problem started at V", you check whether that is what you see. It often will be. Sometimes it will not.

## What using this skill badly looks like

There is no version of the skill that prevents this. There is only your decision not to do it.

- **Bulk-generating feedback you do not read.** The artefact exists. The teaching does not.
- **Sending Claude's output to students without adapting it.** The student gets generic feedback that misses what is specific about them.
- **Letting Claude run Mode 1 conversations with students you never speak to.** Claude is standing in for the teacher conversation. If the teacher conversation never actually happens, the framework has produced compliance, not learning.
- **Reading Claude's review and feeling you understand the student's gap when you have not interrogated that understanding.** This is the illusion of mastery, applied to teaching. Same mechanism, same risk.

## The test

If you use this skill in any of the ways above, you have used VERIFY to demonstrate the framework's central failure mode. The skill cannot stop you. The framework does not need to. Naming the failure mode is the whole point of the framework.

Use the skill the way you would want a student to use AI. Read what you receive. Question it. Adapt it. Make sure the thinking is still yours.

That is the test of whether you understand VERIFY. The skill is one of the places you will be tested.
